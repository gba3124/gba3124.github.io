Privacy Policy

WordKit does not collect, transmit, or sell any personal data.

Last updated: 2026-10-12.

It has no analytics, no tracking, no accounts, and no servers.

Everything WordKit does happens locally in your browser. Counting, fee calculation, punctuation fixing and PDF reflow are pure text transforms that run on your device. There is no network request anywhere in the extension.

Your text

Text reaches WordKit three ways, and none of them leaves your device:

  • You paste or type it into the panel's text box.
  • You select it on a page and open the panel (toolbar button or ⌥⇧W / Alt+Shift+W). The selection you had is brought into the panel, and while the panel is open, new selections in that tab follow into it. If the panel already holds text you wrote, a selection never replaces it: the panel offers to swap it in or add it at the end. A selection inside an editor that sits in a frame of the same site (TinyMCE, the WordPress classic editor) is read the same way. A selection inside a frame from another site can only be read where Chrome has already given WordKit access to that site (the every-site option below); otherwise the panel says so and shows how to copy and paste instead.
  • You select it on the page where you opened the panel (or on any page, if you switched on "show on every site", below). A small badge next to the selection shows its count and fee. The badge reads the selection inside the page to count it; the text is not stored or sent anywhere. The badge and the follow-along ignore selections over 200,000 characters; opening the panel brings in a selection of any size.

Each tab has its own panel text. It is kept in chrome.storage.session, together with its undo history, so that closing the panel, or moving to another page in the same tab, loses neither; closing the tab drops it. Session storage lives in memory only: it is never written to disk or synced, and it is cleared when you quit the browser. The 清除 / Clear button empties the text at once (and 復原 / undo can bring it back while the panel is open). A text over 500,000 characters is not kept when the panel closes; the panel warns you while it holds one. Session storage holds about 10 MB for all tabs together: if it fills up, the text of the least recently used tabs is removed first; the panel that made room tells you how many, and a tab whose text was removed says so when you open its panel.

An extension update clears session storage. So that an update does not lose your text, the panel also hands it to a small hidden page of WordKit inside the same tab, which holds it in memory only and gives it to the panel of the new version. That copy goes when the tab navigates or closes. The web page can see that a hidden WordKit frame is there, but it cannot read it, and copies of it a page might add hold nothing.

WordKit's pages inside web pages (the panel and that hidden page) are loaded from addresses that change every browser session: a site cannot load them by itself, or probe for them to find out whether WordKit is installed. A page on which you open the panel can see that it is there.

WordKit keeps no history of what you counted.

Permissions

  • activeTab — lets WordKit read the page only when you invoke it (toolbar button or keyboard shortcut), so it can bring in your selection and show the panel there.
  • scripting — injects the panel into that tab when you open it, and reads a selection from the tab's frames when it is inside an embedded editor.
  • storage —
    • chrome.storage.sync holds your settings so they follow your Chrome profile: the fee basis, rate, unit and currency, the last three rate combinations you used (numbers only, no text), the interface language, the theme, and which punctuation and reflow fixes to apply.
    • chrome.storage.local holds the panel's on-screen position, the number printed on your quote slips (No. 000012: how many quotes you have copied), and a counter behind the one-time "leave a review" prompt.
    • chrome.storage.session holds each tab's panel text and its undo history, as described above.
    The developer has no access to any of these.

Optional: show the badge on every site

Off by default. Only if you switch on "在所有網站顯示 / On every site" in the panel does WordKit ask Chrome for access to all sites (<all_urls>), so the badge can appear as you select text anywhere without clicking the toolbar first. Chrome shows its own permission prompt; nothing changes if you decline. Switching it off removes the script from every site and gives the permission back; removing the permission in Chrome's extension settings does the same. Even with it on, the badge only counts what you select, in the page, and sends nothing anywhere.

Without that option WordKit has no standing access to any site: it does nothing on a page until you open it there.

Network

There is no network request in WordKit. Its translations and other resources are read from files inside the extension package with chrome.runtime.getURL(), which never touches the network.

The only external address anywhere in the extension is the Chrome Web Store review page, opened only if you click the "leave a review" link yourself.

Data use declarations

For the Chrome Web Store's data-use section, WordKit declares that it does not collect or use any of the listed user-data categories, and it meets all three certifications: no sale of data to third parties, no use for purposes unrelated to the single purpose, and no use to determine creditworthiness or for lending.

Changes

If this policy ever changes, the revision date above changes with it. Any change affecting what the extension does with your data ships alongside the extension update that introduces it.
